# supermono for PTP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `dist/ptp.css`, `ptp-dark.css`, `ptp-light.css` that make PTP look like supermono's BTN sheet, without changing BTN's output.

**Architecture:** `src/shared/00-tokens.css` (unchanged tokens) plus per-tracker rule files in `src/btn/` and `src/ptp/`; `build.sh` loops over trackers. `scrub.mjs` learns trackers from the SingleFile header, strips PTP's theme block and PTP secrets, and writes `fixtures/captured/<tracker>/`. The fixture harness gains a tracker picker. PTP rules are then written page group by page group against scrubbed captures.

**Tech Stack:** bash, perl, `npx lightningcss-cli@1.33.0`, `npx browser-sync@3.0.4`, Node 24 ESM scripts, `node --test` (built in; no package.json).

**Spec:** `docs/superpowers/specs/2026-11-03-ptp-design.md`

## Global Constraints

- `dist/btn.css`, `dist/btn-dark.css`, `dist/btn-light.css` stay byte-identical to the pre-change build (`cmp` after every task that touches `src/` or `build.sh`).
- No package.json, nothing installed into the repo; tool versions pinned exactly as above.
- Nothing identifying in tracked files: no usernames, passkeys, tokens, emails, real name, absolute home paths. `fixtures/captured/` stays gitignored.
- Never print a secret value to the terminal or logs, including during discovery.
- No automated access to PTP or BTN. Markup comes only from the author's captures.
- Git: commit only after the user says so in this session. Commit from inside the repo (repo-local `goozelabs` identity) with `TZ=UTC`; never `--no-verify`. Message style: short imperative subject ≤50 chars, blank line, one-line bullets, wrapped at 72.
- Every text colour passes WCAG AA 4.5:1 in light and dark (`node scripts/contrast.mjs`).
- Scheme-dependent rules use `light-dark()`; at most one `@media (prefers-color-scheme: light)` block per tracker.
- Tracker hosts: BTN host → `btn`, PTP host → `ptp`. Stylesheet link in fixtures: `/dist/<tracker>.css`.
- PTP theme fingerprint: a `<style>` whose content starts with `/*! normalize-scss`.

## Review Focus

1. A capture from an unknown host, or with no SingleFile `url:` header, must be refused with the raw file kept (Task 3 test `refuses unknown tracker`).
2. A PTP capture taken *with* supermono set has no normalize block; that is fine, not an error. Only more than one is an error (Task 3 tests `ptp without theme block` and `two theme blocks refused`).
3. A PTP secret outside an `href`/`value` attribute (inline JS variable, `data-*` attribute, RSS link text) must still be caught by the leftover check (Task 4 test `leftover in inline script refused`).
4. A tracker with no `@media (prefers-color-scheme: light)` block still gets valid forced files: `ptp-dark.css` has `color-scheme:dark`, `ptp-light.css` has `color-scheme:light` (Task 1 step 5).
5. A harness `localStorage` page saved before the tracker split (`captured/foo.html`) must fall back to the tracker's first page, not a blank frame (Task 5 step 4).

### Task 4: PTP secret discovery and patterns

**Files:**

- Modify: `scripts/scrub.test.mjs`

**Interfaces:**
- Consumes: `scrub`, `detectTracker` from Task 3.
- Produces: `node scripts/scrub.mjs --shapes files…` — prints, per file, candidate secrets as `kind name host len charset count` (e.g. `param torrent_pass - 32 [A-Za-z0-9] 14`), never values, never writes or deletes. PTP patterns added to `scrub`.

- [ ] **Step 1: Implement `--shapes`**: candidates are query params named like `auth|key|pass|token|csrf|session` (case-insensitive), path segments of 24+ `[A-Za-z0-9]` chars (report host), `data-*` or JS assignments whose name matches the same word list, and emails (count only). Charset is summarised from the value's character classes.

Always include `leftover in inline script refused`: a PTP page with `<script>var authkey = "<32 chars>";</script>` left un-redacted by the patterns must make `scrub` throw `/survived/`. The PTP leftover check is name-based over the whole document: any secret name found in Step 2 (at least `authkey`, `passkey`, `torrent_pass`) followed by `=`/`:`, optional quote, and a value other than `REDACTED`. It does not scan for bare 32-char strings, which would hit data URIs.
